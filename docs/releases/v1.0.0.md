# v1.0.0: the production record

bradthome.com moved from v0 to v1.0.0 on 2026-11-04 ([#29](https://github.com/memorex386/bradthome/issues/29), [#30](https://github.com/memorex386/bradthome/pull/30), [D113](../decisions/0113-releases-run-from-a-tag-behind-brads-approval.md)). This is SC-001's evidence. The runbook is [docs/release.md](../release.md).

## The release

- Tag: `v1.0.0`, signed, on main's `c46ce89`. GitHub release: [v1.0.0](https://github.com/memorex386/bradthome/releases/tag/v1.0.0).
- Run: [release 41876609236](https://github.com/memorex386/bradthome/actions/runs/41876609236). The stage job put version `0749adf539329b20` on the `release` channel. Its pre-release check against v0 on bradthome.com printed:

  ```text
  ✓ check  https://bradthome--release-gn6n25b2.web.app serves every URL, redirect, security header and word that https://bradthome.com does (9 URLs, 2 pages' words)
  ```

- Brad approved the release job in `production`. The first attempt couldn't sign in. Google refused `release-deployer` with HTTP 403 before anything changed, because the Workload Identity binding named `repo:memorex386/bradthome:environment:production`. This repo uses GitHub's immutable subject claim, so the binding now names `repo:memorex386@11021156/bradthome@1440242332:environment:production`, as the runbook notes. After the fix, Brad approved the re-run, and the release job printed:

  ```text
  ✓ release  version 0749adf539329b20 is served on live at https://bradthome.com: 10 files, after 1 s
  ```

## Checked afterwards

`pnpm release:status`:

```text
✓ status  live (https://bradthome.com) serves version 0749adf539329b20, released 2026-11-04T18:42:19.142Z: v1.0.0 (c46ce89)
  A rollback would put back version 1a8537e6c37af51e.
```

v0's version `1a8537e6c37af51e` was put on the preview channel `v0`, which expires after 30 days. Then the pre-release check ran with bradthome.com as the candidate and v0 as the baseline:

```text
✓ rollback  version 1a8537e6c37af51e is served on v0 at https://bradthome--v0-0wypu31b.web.app: 6 files, rollback served after 1 s
✓ check  https://bradthome.com serves every URL, redirect, security header and word that https://bradthome--v0-0wypu31b.web.app does (9 URLs, 2 pages' words)
```

curl against bradthome.com:

| Request | Answer |
| --- | --- |
| `/`, `/vindecoded-agents`, `/favicon.svg` | 200 |
| `/no-such-page` | 404, with the site's 404 page |
| `/index.html` | 301 to `/` |
| `/vindecoded-agents/` | 301 to `/vindecoded-agents` |
| `www.bradthome.com` | 301 to `https://bradthome.com/` |

Security headers on `/`, where v0 sent only Hosting's `Strict-Transport-Security: max-age=31556926`:

- `Strict-Transport-Security: max-age=63072000; includeSubDomains`. This is `firebase.json`'s own value. On the custom domain, Hosting sends it in place of its default, which settles D99's open point.
- `Content-Security-Policy` with hashes from the build, and `X-Content-Type-Options: nosniff`.
- `Referrer-Policy: strict-origin-when-cross-origin`, and a `Permissions-Policy` that blocks every listed feature.

## Rollback

A rollback puts v0 back. `pnpm release:status` names it, and the rehearsal ([rehearsal.md](rehearsal.md)) served its rollback in 1 second. v0's source folder stays outside the repo as the fallback.
