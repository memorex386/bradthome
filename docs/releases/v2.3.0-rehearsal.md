# Rehearsal: release v2.3, roll back to v2.2

The rehearsal for v2.3.0, which releases the landing study's direction A slices A1–A4 together (specs 025–028), run on 2026-11-10 from main's `19913df`, before v2.3 reached the live channel. It ran on preview channels of the `bradthome` site only, with the scripts the release and rollback workflows run, as Brad's own login, as the [v2.2.0 rehearsal](v2.2.0-rehearsal.md) did.

## Setup

- The candidate was `19913df`'s build, made in the pinned Playwright container by `pnpm test:visual`, with the résumé PDFs printed and `pnpm csp --check` passing. It was deployed with the repo's `firebase.json` to channel `v23-rc` as version `585ee1281d15cd47`.
- Releases went to channel `rehearsal-v23`, created for the rehearsal, expiring a day later.
- v2.2.0, which bradthome.com serves, is version `3ef869c390b26244` (`pnpm release:status`).

## The pre-release check

Against bradthome.com. Without a flag it stops on the home's words, since A1 moved the role switch under the hero and added the proof tiles:

```text
$ pnpm release:check --candidate https://bradthome--v23-rc-m8po4kxq.web.app
✖ check  words differ on /: live has “2026 Open LinkedIn Close Hiring for Any role Mobile Full-stack Applied AI”, candidate has “2026 Open LinkedIn Close Senior mobile & full-stack engineer · Dallas–Fort Worth”
```

With only the home's words allowed to change, as the release runs with `words-may-change=home`:

```text
$ pnpm release:check --candidate https://bradthome--v23-rc-m8po4kxq.web.app --home-words-may-change
– check  Hosting sets its own HSTS on bradthome--v23-rc-m8po4kxq.web.app, so the check reads firebase.json at 19913df's: max-age=63072000; includeSubDomains
```
