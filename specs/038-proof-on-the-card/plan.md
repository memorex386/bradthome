## Alternatives considered

- **Rename the anchors to `#claim-<id>`:** cleaner names, but `/corpus.json` and `/llms.txt` would change, the chat API would need a redeploy, and every source link in an answer already given would stop landing. Keeping `receipt-` costs nothing a visitor sees.
- **The sparkle as a `<button>`:** it would need script to do anything, and with none it would do nothing. A link to Contact works everywhere, and the existing hand-over takes it.
- **A tooltip centered on the sparkle:** at a line's end on a phone it could pass the screen's edge, where the page clips it. Ending it at the sparkle keeps it whole.
- **Every source in the list, even those a stat or link shows:** simpler, but four would repeat a link on the same card, the clutter the study counted.
- **Retitle the 20 kept cases to "“Ask about this” on …":** consistent on `/evals`, but it changes their hashes, so the changed run would ask all 30, including one that missed its accuracy check in the last full run. They can change with the next full run.

## Risks

- **Many tests and baselines pin the drawers.** About twenty specs' tests name markers, drawers, "Ask me" or the numbers; each is amended in this branch to what the spec now says, and the reviewer checks none was weakened. Specs 001–003 name no receipt, so their locks don't move.
- **The 44 px target over the line.** It reaches about 9 px above and below a claim's last line, over text that isn't a link. A test measures every sparkle at 320, 375, 390, 1280 and 1440 px on all four pages and fails on any overlap, so a later claim that crowds one is caught.
- **Two outside pages back the Capital One card.** They show at rest now; the nightly link check still reports them if they go.
- **The eval run** costs cents (a changed run of three cases cost $0.018). A new case that fails twice fails the run; then the case or the claim's wording is fixed, never the bar.
